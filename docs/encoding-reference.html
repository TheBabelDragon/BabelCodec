Encoding reference

Concepts behind BabelCodec’s converters and inspectors. Examples use the same semantics as the live workbench.

Binary representation

Computers store data as bits (0 or 1). Eight bits form a byte (values 0–255). Text, images, and machine code are all sequences of bytes interpreted by a convention.

Bits and bytes

A bit is the smallest unit. A byte is 8 bits. Offsets in the Hex Inspector are byte positions starting at 0.

ASCII versus Unicode

ASCII covers 128 characters (0–127). Unicode assigns a code point to characters across writing systems. BabelCodec’s ASCII path is strict; the UTF-8 path accepts full Unicode text.

UTF-8 byte encoding

UTF-8 encodes each Unicode code point as 1–4 bytes. ASCII characters remain single bytes.

"A"  → 41
"€"  → E2 82 AC
"あ" → E3 81 82

Hexadecimal representation

Each byte is shown as two hex digits (00–ff). Hex is a readable view of the same bytes as binary.

Base64 versus binary

Base64 maps binary data to a 64-character ASCII alphabet so it can travel through text-only channels. It is reversible and is not encryption.

Text encoding versus hashing

Encoding (UTF-8, hex, Base64, Morse) is reversible when the rules are followed. Hashing (SHA-256) is one-way: the digest does not recover the original input.
